관련 문서 README · 테스트 결과 · 화면 캡처

이 문서의 시장 규모·누수 금액·가격·재무 수치는 검증 전 가정입니다. 가정마다 근거와 검증 방법을 함께 적었고, 파일럿(8주)에서 실측해 고칩니다.

1. 한 줄 요약

문의 접수 → 현장 확인 → 견적 → 고객 승인 → 작업 배정 → 자재 사용 → 완료 정산을 한 흐름으로 묶고, 소규모 배관 업체가 돈과 신뢰를 가장 많이 잃는 네 지점 — 추가 작업 승인 누락, 자재 중복 예약, 작업팀 일정 충돌, 청구 누락 — 을 자동으로 찾아내 금액으로 보여 주는 모바일 우선 웹앱입니다.

2. 문제 정의

2.1 대상 업체가 일하는 방식 (인터뷰로 검증할 가설)

  • 직원 1~10명. 대표가 기사·영업을 겸하고, 전화·견적·정산은 가족이나 사무장 1명이 맡는다.
  • 문의는 전화·카카오톡·문자·관리사무소로 들어오고, 수첩·화이트보드·엑셀에 적는다.
  • 견적은 현장에서 말로 하거나 문자로 보낸다. 양식이 제각각이고 승인 기록이 남지 않는다.
  • 현장에서 "하는 김에" 추가 작업을 말로 합의하고 진행한다.
  • 자재·장비 재고는 대표의 기억과 차량 적재 상태에 의존한다.
  • 청구서·세금계산서는 월말에 몰아서 처리하고, 미수금은 통장을 보고 기억으로 챙긴다.

2.2 돈이 새는 네 지점

지점 현장에서 흔한 상황 결과
① 추가 작업 승인 누락 수전 교체 중 트랩 부식 발견 → 고객 부재로 "일단 교체" 청구하면 "그런 말 들은 적 없다" → 분쟁·무상 처리
② 자재 중복 예약 재고 PVC관 7본을 두 현장에 각각 4본·6본 약속, 고압 세척기 1대를 같은 시간 두 팀이 사용 현장 헛걸음, 자재상 재방문, 작업 지연
③ 작업팀 일정 충돌 긴급 건을 기존 일정에 끼워 넣음, 대표가 두 팀에 동시에 들어감 약속 불이행, 고객 대기, 재방문 비용
④ 청구 누락 완료 후 청구서 미발행, 추가 작업분 누락, 미수금 방치 매출 누수, 현금 흐름 악화

네 문제는 따로 생기지 않습니다. 기록이 여러 곳(수첩·카톡·엑셀·기억)에 흩어져 있어서 서로 대조되지 않는다는 한 가지 원인에서 나옵니다. 그래서 해법도 "기록을 한 흐름으로 묶고, 흐름이 끊긴 곳을 기계가 대조해 찾는 것"입니다.

2.3 문제의 크기 — 업체 1곳 기준 추정 (가정)

누수 항목 가정 월 금액
추가 작업 미청구·무상 처리 월 3건 × 평균 15만 원 45만 원
청구 누락·지연으로 못 받은 돈 월 매출 3,000만 원의 1% 30만 원
자재·장비·일정 충돌로 인한 헛걸음·재방문 월 2회 × 15만 원(2인 반나절 인건비 + 유류) 30만 원
합계 월 약 105만 원 (매출의 약 3.5%)
  • 가정 업체: 월 매출 3,000만 원, 월 작업 60건, 작업팀 2~3개.
  • 이 금액이 파일럿에서 가장 먼저 실측할 핵심 가설입니다. 파일럿 업체의 지난 3개월 장부를 앱에 옮겨 넣으면 탐지 엔진이 실제 누락 건수·금액을 계산해 줍니다(데이터 이관 시에도 규칙이 동작하도록 설계).

3. 목표 고객과 사용자

3.1 목표 고객

  • 1차 시장: 수도권의 1~10인 배관·설비 업체 (하수구·막힘, 누수 탐지, 급수관·배수관 교체, 보일러 배관).
  • 2차 시장: 인접 업종 — 방수, 욕실 리모델링, 냉난방 설비 등 "현장 확인 → 견적 → 현장 작업 → 추가 작업"이 반복되는 소규모 시공업.
  • 고객의 고객: 개인 가정, 상가, 관리사무소. 특히 관리사무소는 증빙(서명·견적서)을 요구하므로 "고객 링크 서명"이 그대로 판매 포인트가 됩니다.

3.2 사용자(페르소나)

사용자 하는 일 앱에서 가장 많이 쓰는 기능 기대 효과
대표 (52세, 현장+영업) 견적·배정 결정, 현장 작업 '오늘' 화면의 "지금 놓치고 있는 돈", 점검 센터 월말에 새는 돈을 그날 바로 확인
사무장 (45세) 전화 접수, 견적서, 정산 문의 접수, 견적 작성·발송, 청구서 발행 누락 없는 청구, 전화 문의 기록
현장 기사 (34세) 작업, 자재 사용, 추가 작업 발견 휴대폰: 자재 사용 기록, 추가 작업 요청 + 현장 서명 구두 약속 대신 서명 한 번
고객 견적·추가 작업 승인 문자로 받은 링크에서 확인·서명 (앱 설치 없음) 금액을 미리 알고 결정

4. 솔루션

4.1 7단계 업무 흐름과 단계별 안전장치

작업건 하나가 7단계를 차례로 지나며, 각 단계는 **다음 단계로 넘어가는 조건(가드)**을 가집니다. 조건이 안 맞으면 시스템이 이유를 한국어로 설명하고 해결 버튼을 보여 줍니다.

단계 화면에서 하는 일 넘어가는 조건 · 자동 처리
1. 문의 접수 고객·주소·증상·접수 경로·긴급도 입력 신규 고객 자동 등록
2. 현장 확인 방문 팀·시간 예약, 확인 결과 입력 팀 일정 충돌 시 예약 거부 + 빈 팀 추천
3. 견적 자재 목록·인건비 빠른 추가, 부가세 자동 계산, 버전 관리 빈 견적 발송 불가, 발송본 수정 불가(새 버전 생성)
4. 고객 승인 고객 링크 서명 / 현장 서명 / 문자 회신 / 전화(구두) 기록 서명 방식은 서명 필수, 승인 방법·시각·승인자 기록
5. 작업 배정 팀·일정 배정, 자재·장비 예약 승인 견적 없으면 배정 불가, 일정·재고·장비 충돌 차단
6. 자재 사용 현장에서 사용 수량 기록, 추가 작업 요청·서명 예약에서 자동 차감, 승인 수량 초과 시 즉시 경고
7. 완료 정산 작업 완료, 청구서 발행, 수금 기록, 원가·이익 계산 승인 없는 추가 작업·초과 사용이 있으면 완료 불가, 승인 항목 자동 청구

4.2 4대 누락·충돌 탐지 엔진

세 가지 원칙으로 설계했습니다.

  1. 예방: 입력하는 순간 막는다 (배정·예약·완료·청구 명령이 거부되고 이유와 대안을 보여 줌).
  2. 탐지: 현장 사정으로 강제 진행하거나 데이터를 옮겨 온 경우에도, 저장된 플래그가 아니라 현재 데이터 전체를 매번 다시 검사해 찾아낸다.
  3. 해소: 모든 탐지 항목에 "해결 화면으로 가는 버튼"과 위험 금액이 붙는다. 긴급 항목은 원인을 없애야만 사라지고, 주의·참고 항목은 사유를 남겨야 확인 처리된다.
분류 탐지 규칙 심각도
① 추가 작업 승인 누락 승인 기록 없는 추가 작업이 수행됐거나 그 작업에 자재가 쓰임 긴급
견적·추가 작업 어디에도 없는 수량만큼 자재를 더 씀 작업 중 주의 / 완료 후 긴급
승인 견적 없이 작업이 배정·진행됨 긴급
추가 작업 요청 후 24시간 동안 승인 없음 주의
30만 원 이상 추가 작업을 전화(구두)로만 승인 참고
② 자재 중복 예약 소모 자재 예약 합계 > 보유 재고 (같은 재고를 여러 작업이 잡음) 긴급
장비: 같은 시간대 필요 대수 > 보유 대수 (스윕 라인 알고리즘) 긴급
한 작업에 같은 자재 예약이 두 줄 이상 주의
완료·취소된 작업의 예약이 남아 재고를 묶음 주의
예약 후 가용 재고 < 안전 재고 참고
③ 작업팀 일정 충돌 한 팀이 같은 시간 두 현장(작업·현장 확인 포함) 긴급
두 팀에 모두 속한 사람이 겹치는 시간 양쪽에 필요 긴급
같은 날 연속 일정 사이 이동 시간 30분 미만 주의
예정 시간이 지났는데 결과·착수 기록 없음 주의
④ 청구 누락 완료 후 1일 경과 청구서 없음 (3일 이상 긴급) 주의→긴급
승인된 추가 작업이 청구서에서 빠짐 긴급 (사유 기록 시 주의)
청구액 < 고객 승인 금액 (수기 수정 등) 긴급
결제 기한 지난 미수금 (30일 이상 긴급) 주의→긴급

기준값(이동 시간, 청구 기한, 구두 승인 금액 등)은 업체별로 바꿀 수 있습니다.

4.3 현장 우선 설계

  • 휴대폰에서 3번 탭 안에: 오늘 일정 → 작업건 → "자재 사용 기록" / "추가 작업 요청".
  • 추가 작업 = 요청 + 서명 한 번: 요청을 만들면 곧바로 서명 화면이 열리고, 고객이 기사 휴대폰에 손가락으로 서명합니다. 고객이 없으면 승인 링크를 문자로 보냅니다.
  • 고객은 앱 설치 없이: 링크에서 견적서·추가 작업 내역과 금액을 보고 서명합니다. 공개 화면에는 원가·내부 메모가 나가지 않습니다.
  • 대표는 금액으로: '오늘' 화면 첫 줄에 "지금 놓치고 있는 돈"과 4대 위험 건수를 보여 줍니다.

5. 대안과 차별점

대안 한계
수첩·화이트보드·엑셀·카카오톡 기록이 흩어져 대조가 안 됨 → 네 가지 누수의 원인 그 자체
범용 ERP·그룹웨어 배관 현장 흐름(현장 확인, 추가 작업, 장비 예약)에 맞지 않고, 1~10인 업체가 쓰기에 무겁다
해외 현장 관리(FSM) SaaS 한국어·부가세·현장 서명 관행·관리사무소 거래 방식에 맞추기 어렵고, 소규모 업체 가격대와 거리가 있음 (가정 — 경쟁 조사로 확인)
일반 일정·견적 앱 일정, 견적, 재고, 청구가 서로 연결되지 않아 "빠진 것"을 찾아 주지 못함

차별점

  1. 기록 도구가 아니라 "빠진 것을 찾아 주는" 도구. 견적·추가 작업·예약·사용·일정·청구를 서로 대조하는 규칙 엔진이 핵심입니다.
  2. 추가 작업 서명 → 청구 자동 반영. 승인된 추가 작업은 청구서에 자동으로 들어가고, 빼려면 사유가 필요합니다.
  3. 1인 업체도 쓰는 단순함. 휴대폰 한 손 조작, 설치 없는 웹앱, 한국어 현장 용어.
  4. 효과가 금액으로 보임. "이번 달 탐지·회수 금액"이 곧 구독을 유지하는 이유가 됩니다.

요금제 월 요금 (VAT 별도) 대상 포함

기본 29,000원 1~2팀 무제한 작업건, 고객 링크 승인, 정산
프로 59,000원 3~5팀 장비 예약, 인원 공유 팀, 월간 리포트, 우선 지원

부가 매출: 알림톡·문자 발송(건당, 원가 + 마진), 전자세금계산서 연동(월 정액), 결제 링크 수수료(결제 대행사 제휴).

고객 입장 ROI (가정): 2.3의 월 105만 원 누수 중 30%만 막아도 월 31.5만 원 → 프로 요금 5.9만 원의 약 5배. 파일럿에서 "첫 달 탐지 금액"을 영업 자료로 씁니다.

7. 시장 진입 전략

  1. 자재 도매상 제휴 (핵심 채널): 배관 업체는 매주 자재상을 찾습니다. 카운터 QR·전단, 제휴 업체 첫 3개월 할인, 자재상에는 소개 수수료. 이후 자재상 단가·재고 연동으로 확장.

  3. 설비인 커뮤니티·유튜브: "추가 작업 분쟁 안 생기는 법", "월말 미수금 정리" 같은 실무 콘텐츠.
  4. 30분 방문 세팅: 팀·자재 20개·인건비 단가 등록을 대신 해 주고 첫 작업건을 함께 입력. 첫 달 무료.

9. 운영·기술 계획

  • 구조: 업무 규칙(명령·탐지)을 순수 JavaScript "업무 엔진"으로 만들어 서버와 브라우저가 같은 코드를 씁니다. 그래서 서버 없이 도는 단독 데모가 가능하고, 이후 현장 오프라인 입력(전파가 약한 지하 기계실)으로 확장하기 쉽습니다.
  • 데이터 무결성: 모든 변경은 명령 단위 트랜잭션(복사본에서 실행 후 성공 시에만 반영)이고, 누가·언제·무엇을 했는지 이력이 남습니다. 저장은 임시 파일 → 이름 바꾸기로 원자적으로 처리합니다.
  • 보안·개인정보: 고객 이름·연락처·주소는 개인정보입니다. 정식 출시 전 개인정보 수집·이용 동의, 역할별 접근 권한, 보관 기간·파기, 전송 구간 암호화, 백업을 갖춥니다. 고객 승인 링크는 추측할 수 없는 토큰을 쓰고, 공개 화면에는 원가·내부 메모를 보내지 않습니다. 서버는 CSP 등 보안 헤더와 요청 크기 제한, 경로 조작 차단을 적용했습니다.
  • 현재 MVP의 한계 (정직하게): 로그인·권한이 없고(데모용 사용자 선택만), 저장소가 단일 JSON 파일이며, 문자 발송·세금계산서·결제는 연동되지 않았습니다. 파일럿 전에 1순위로 해결합니다.

  • 어느 날짜에 만들어도 같은 구조가 된다(날짜 상대값).

7. 알려진 한계

  • 로그인·권한이 없습니다(데모용 사용자 선택). 공개 API 외 모든 API가 인증 없이 열려 있으므로 인터넷에 그대로 공개하면 안 됩니다. 사업 기획서 10장 로드맵의 1순위입니다.
  • 저장소는 단일 JSON 파일(원자적 쓰기)로, 동시 사용자가 많은 환경을 위한 것이 아닙니다.
  • 문자·알림톡 발송, 전자세금계산서, 결제는 연동하지 않았습니다(링크 복사로 대체).
  • E2E는 Chromium 엔진으로만 실행했습니다(휴대폰은 Pixel 7 에뮬레이션). iOS Safari 실기기 검증은 파일럿에서 진행합니다.
